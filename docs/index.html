ลำดับความสำคัญ: 🔴 ต้องแก้ก่อนใช้จริง · 🟠 ควรแก้ · 🟡 ปรับปรุง

🔴 1. แข่งสด: คะแนนผู้เล่นขึ้นก่อนครูเปิดเฉลย

อาการ: ภาพ 4-live/10 ขึ้น "ส่งคำตอบแล้ว รอผล…" แต่หัวจอแสดง 935 คะแนนแล้ว ผู้เล่นรู้ทันทีว่าตอบถูก
สาเหตุที่น่าจะเป็น: เซิร์ฟเวอร์ส่ง event อัปเดตคะแนน (หรือส่ง score กลับมากับ ack ตอนส่งคำตอบ) ทันทีที่ตรวจคำตอบ
วิธีแก้:

  • ตอนรับคำตอบ: เก็บผลไว้ใน state ของรอบนั้นอย่างเดียว ส่งกลับแค่ { received: true }
  • ส่งคะแนนให้ผู้เล่นพร้อม event เฉลย (reveal) เท่านั้น
  • ฝั่ง client: แถบคะแนนอ่านค่าจาก event reveal/leaderboard ไม่อ่านจาก ack
// ตอนรับคำตอบ
socket.on("answer", (a, ack) => {
  const r = grade(room.currentQuestion, a);
  room.pending.set(player.id, r);          // ยังไม่บวกคะแนนที่ส่งให้ผู้เล่น
  ack({ received: true });                 // ห้ามส่ง score กลับ
});
// ตอนครูกดเฉลย / หมดเวลา
function reveal(room) {
  for (const [id, r] of room.pending) room.score[id] += r.points;
  io.to(room.id).emit("reveal", { answer, leaderboard: rank(room) });
  for (const p of room.players) io.to(p.socketId).emit("you", { correct: room.pending.get(p.id)?.correct ?? false, gained: room.pending.get(p.id)?.points ?? 0, total: room.score[p.id] });
  room.pending.clear();
}

ตรวจว่าแก้แล้ว: ส่งคำตอบถูก → หัวจอยังแสดงคะแนนเดิมจนกว่าครูจะกดเฉลย

🔴 2. ลิงก์เข้าร่วม/QR และลิงก์แชร์เป็น localhost:3100

อาการ: มือถือนักเรียนสแกน QR แล้วเข้าไม่ได้
วิธีแก้: สร้าง URL จากตัวแปรตั้งค่า ไม่ใช้ค่าตายตัวหรือ host ของเครื่อง

// config.ts
export const PUBLIC_URL = (process.env.PUBLIC_BASE_URL ?? "").replace(/\/$/, "");
// ถ้าไม่ได้ตั้ง ให้ใช้ origin ของ request ที่เข้ามา (ใช้ได้เมื่อเปิดผ่าน IP ในวง LAN)
export const baseUrl = (req) => PUBLIC_URL || `${req.headers["x-forwarded-proto"] ?? "http"}://${req.headers.host}`;
  • หน้าโฮสต์, QR, ปุ่ม "คัดลอก" ลิงก์แชร์ → ใช้ baseUrl ทั้งหมด
  • ใส่ PUBLIC_BASE_URL= ใน .env.example และ README ตรวจว่าแก้แล้ว: เปิดจาก IP เครื่อง (เช่น 192.168.x.x:3100) → QR พาไปที่ IP นั้น

🔴 3. เหรียญ "คะแนนเต็ม" ไม่ปลดล็อก

อาการ: ได้ 300/300 และ 500/500 แต่เหรียญยังล็อก
สาเหตุที่น่าจะเป็น: เงื่อนไขเทียบกับค่าคงที่ (เช่น score === 1000) หรือเทียบ score === maxScore ที่ maxScore คิดผิด (นับโบนัสเวลา/คะแนนต่อข้อเปลี่ยน) หรือเช็กเฉพาะแบบทดสอบ
วิธีแก้: เช็กจาก "ตอบถูกทุกข้อ" แทนตัวเลขคะแนน และเช็กทั้งเกมและแบบทดสอบ

const perfect = result.correctCount === result.totalQuestions && result.totalQuestions > 0;
if (perfect) await awardBadge(userId, "PERFECT_SCORE");
  • เพิ่มสคริปต์ย้อนหลัง: ให้เหรียญกับผู้ใช้ที่เคยได้เต็มไปแล้ว ตรวจว่าแก้แล้ว: เล่นเกมถูกหมด → ขึ้น "ได้รับเหรียญใหม่: คะแนนเต็ม"

🔴 4. Word Scramble ไม่สลับตัวอักษร

อาการ: ภาพ 1-guest/09 แสดง d‑o‑g เรียงตรงคำตอบ
สาเหตุที่น่าจะเป็น: ไม่ได้ shuffle หรือ shuffle แล้วบังเอิญได้ลำดับเดิม (คำสั้นมีโอกาสสูง)

function scramble(word: string) {
  const a = [...word];
  if (new Set(a).size < 2) return a;                // เช่น "aa" สลับไม่ได้
  do {
    for (let i = a.length - 1; i > 0; i--) { const j = Math.floor(Math.random() * (i + 1)); [a[i], a[j]] = [a[j], a[i]]; }
  } while (a.join("") === word);
  return a;
}
  • ใช้ Intl.Segmenter แทน [...word] ถ้ารองรับคำไทย (สระ/วรรณยุกต์ต้องติดกับพยัญชนะ) ตรวจว่าแก้แล้ว: เปิดเกม 20 ครั้ง ไม่มีครั้งไหนเรียงตรงคำตอบ

🟠 5. ข้อความทดสอบหลุดหน้าสาธารณะ

อาการ: คำอธิบายเกมผลไม้มี "(แก้ไขแล้ว)"
วิธีแก้: แก้ข้อมูลตัวอย่าง (seed) กลับเป็นคำอธิบายเดิม และให้สคริปต์ทดสอบที่แก้ข้อมูลทำงานบนฐานข้อมูลทดสอบแยก หรือคืนค่าหลังทดสอบเสร็จ

🟠 6. AI ใช้โมเดลจำลอง / หน้าตั้งค่าแสดงข้อมูลเทคนิคให้ครู

อาการ: ได้คำถาม "คำถามที่ 1… ก/ข/ค/ง" จาก mock-model; หน้า "ยังไม่ได้ตั้งค่า" แสดงชื่อตัวแปร AI_API_KEY ให้ครู
วิธีแก้:

  • โหมดจำลองเปิดได้เฉพาะตอนพัฒนา (NODE_ENV !== "production" และ AI_MOCK=1) ถ้าเป็น production ให้ถือว่า "ยังไม่ได้ตั้งค่า"
  • ครูเห็นแค่ "ฟีเจอร์นี้ยังไม่เปิดใช้ กรุณาติดต่อผู้ดูแลระบบ"; รายละเอียดตัวแปรแสดงเฉพาะผู้ดูแล (หรือใน README)
  • ต้องมีคีย์ API จริงจึงจะได้ผลลัพธ์ AI จริง

🟠 7. คะแนนเฉลี่ยในแดชบอร์ดครูขัดกัน (50% vs 75%)

สาเหตุ: การ์ดด้านบนเฉลี่ยเฉพาะแบบทดสอบ (71+71+29+29)/4 = 50% ส่วนตารางห้องเฉลี่ย "ค่าเฉลี่ยของแต่ละงาน" (50% กับ 100%) = 75%
วิธีแก้ (เลือกอย่างใดอย่างหนึ่ง): ตั้งชื่อให้ชัด เช่น "คะแนนเฉลี่ยแบบทดสอบ" กับ "คะแนนเฉลี่ยทุกงาน" หรือใช้สูตรเดียวกันทั้งสองที่ (แนะนำ: เฉลี่ยจากทุกการส่งงาน)

🟠 8. ข้อความ/รูปแบบที่ยังไม่เป็นไทย

  • ช่องวันที่ mm/dd/yyyy: ใส่ lang="th" ที่ <html> (ส่วนใหญ่เบราว์เซอร์จะตามภาษาเครื่อง) หรือเปลี่ยนเป็นตัวเลือกวันที่ของเอง/แยกช่องวันที่+เวลา แล้วแสดงวันที่ที่เลือกเป็น "2 พ.ย. 2569 16:30" ข้างช่อง
  • ปุ่มเลือกไฟล์ "Choose File No file chosen": ซ่อน <input type="file"> แล้วใช้ <label> เป็นปุ่ม "เลือกรูป" + แสดงชื่อไฟล์ / "ยังไม่ได้เลือกไฟล์"
  • ประวัติแก้ไข 28/10/69: ใช้ฟังก์ชันจัดรูปแบบวันที่ตัวเดียวกับหน้าอื่นทั้งระบบ

🟠 9. เขตเวลา (ต้องยืนยัน)

อาการที่สงสัย: เวลาในกิจกรรม (30 ต.ค. 07:53) ตรงกับเวลาไฟล์ภาพ อาจยังเป็น UTC
วิธีแก้: ฐานข้อมูลเก็บเป็น UTC แต่ทุกจุดที่แสดงผลใช้ฟังก์ชันเดียว

export const fmt = (d: Date | string) => new Intl.DateTimeFormat("th-TH", {
  timeZone: process.env.APP_TIMEZONE ?? "Asia/Bangkok",
  day: "numeric", month: "short", year: "numeric", hour: "2-digit", minute: "2-digit",
}).format(new Date(d));
  • กราฟ "XP 7 วัน" / "14 วันล่าสุด": จัดกลุ่มรายวันตามเวลาไทย ไม่ใช่ UTC
  • ไฟล์ CSV ที่ส่งออก: ใช้เวลาไทยเหมือนกัน ตรวจว่าแก้แล้ว: เล่นเกมตอน 08:00 น. เวลาไทย → ขึ้น 08:00 ไม่ใช่ 01:00

🟡 10. มือถือ

  • เมนูด้านบนกิน 3 บรรทัด: ที่จอ < 640px ให้เหลือโลโก้ + ปุ่ม ☰ เปิดเมนูแบบพับ (รวมเมนูครูไว้ในนั้นด้วย)
  • ตาราง (ความคืบหน้าห้อง, ผลรายบุคคล, ผู้ใช้): ห่อด้วย overflow-x:auto หรือเปลี่ยนเป็นการ์ดเมื่อจอแคบ

🟡 11. สีตัวอักษรอ่านยาก

  • โหมดมืด: ปุ่มม่วงอ่อน + ตัวอักษรขาว → ใช้ตัวอักษรสีเข้ม (#1f1b3a) บนปุ่มม่วงอ่อน หรือใช้ม่วงเข้มแบบโหมดสว่าง
  • ไอคอนปฏิทินในช่องวันที่ใช้ color-scheme: dark ในโหมดมืด
  • แข่งสด ตัวเลือกสีเหลือง: ใช้ตัวอักษรสีเข้ม หรือเปลี่ยนเหลืองให้เข้มขึ้น (#b7791f)
  • เป้าหมาย: ค่าความต่างสี (contrast) ≥ 4.5:1 ตาม WCAG AA

🟡 12. อื่น ๆ

  • หลังล็อกอิน: พานักเรียน/ครูไปแดชบอร์ดของตัวเอง (หรือกลับไปหน้าที่ตั้งใจจะไปก่อนล็อกอิน)
  • ช่อง PIN: เคอร์เซอร์อยู่กลางข้อความ placeholder เพราะ letter-spacing → ใช้ placeholder แบบ "______" หรือลด letter-spacing ของ placeholder
  • ลิงก์ "ผู้ดูแลระบบ" อยู่ในแถบ "เครื่องมือครู" → แยกเป็นแถบ/เมนูของผู้ดูแล
  • งานออกแบบ (ภาพประกอบ/แอนิเมชันตามสเปก) แยกทำเป็นรอบหลังจากแก้บั๊ก
