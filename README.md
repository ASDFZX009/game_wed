# 🧭 QUIZ ODYSSEY

แพลตฟอร์มเกมและแบบทดสอบเพื่อการเรียนรู้สำหรับนักเรียน ครู และผู้ดูแลระบบ เขียนใหม่ทั้งหมด (เวอร์ชัน 2) และแก้ปัญหา 12 จุดที่พบในเวอร์ชันเดิม

- **เกม 5 แบบ:** ถูก/ผิด, ปรนัย (มีรูปและคำใบ้), เรียงลำดับ, เรียงคำ (ไทย/อังกฤษ), พลิกการ์ดจับคู่
- **แบบทดสอบ 10 ชนิดคำถาม:** ปรนัย, ถูก/ผิด, คำตอบสั้น, เติมคำ, จับคู่, เรียงลำดับ, อัตนัย (ครูตรวจ) และชนิดใหม่ ✨ เลือกได้หลายข้อ, ตอบเป็นตัวเลข, เติมคำจากคลังคำ
- **เนื้อหาตัวอย่าง:** 19 เกม (209 ข้อ) และ 7 แบบทดสอบ (75 ข้อ) ครบ 9 หมวดวิชา
- **นักเรียน:** แดชบอร์ด XP/ระดับ เหรียญรางวัล 8 แบบ กราฟ 7 วัน ห้องเรียน งานที่ต้องทำ
- **ครู:** ห้องเรียน มอบหมายงาน (ตัวเลือกวันที่แบบไทย) รายงาน + CSV ตัวสร้างแบบทดสอบ/เกม ประวัติเวอร์ชัน ตรวจข้ออัตนัย AI ช่วยสร้าง
- **แข่งสดเรียลไทม์:** PIN + QR, โหมดทีม, หยุด/ข้ามข้อ, เชิญผู้เล่นออก, CSV ผลการแข่ง
- **ผู้ดูแลระบบ:** สถิติ จัดการผู้ใช้ (บทบาท/ระงับ/ตั้งรหัสใหม่) ตรวจสอบเนื้อหา หมวดหมู่ บันทึกการดำเนินการ
- **หน้าตั้งค่า:** ธีมสี 6 แบบ, โหมดสว่าง/มืด/ตามอุปกรณ์, ขนาดตัวอักษร 4 ระดับ, ความต่างสีสูง, เว้นระยะตัวอักษร, ลดการเคลื่อนไหว, เสียงประกอบ, พลุฉลอง, ไปข้อถัดไปอัตโนมัติ — สมาชิกบันทึกกับบัญชี (ตามไปทุกเครื่อง) ผู้เยี่ยมชมบันทึกในเบราว์เซอร์
- **ร้านค้า 🛒:** ใช้เหรียญ 🪙 จากการเล่นเกม/ทำแบบทดสอบ (แยกจาก XP — ซื้อของแล้วระดับไม่ลด) แลกของตกแต่ง 43 ชิ้น 6 หมวด: อวาตาร์, กรอบรูป, ฉายา, ธีมพิเศษ, เอฟเฟกต์ฉลอง, พื้นหลัง — ของที่ใส่จะแสดงบนเมนู แดชบอร์ด โปรไฟล์ อันดับในห้อง และแข่งสด
- **กล่องสุ่ม 🎁:** กล่องธรรมดา (เปิดฟรีวันละครั้ง) และกล่องทองคำ แสดงโอกาสได้ของแต่ละระดับชัดเจน ได้ของซ้ำคืนเหรียญ ของระดับตำนานได้จากกล่องเท่านั้น ไม่มีการซื้อด้วยเงินจริง
- **มือถือ 📱:** แถบเมนูด้านล่างแบบแอป, ปุ่มขนาดแตะง่าย, เลย์เอาต์จัดใหม่สำหรับจอ 360–760px, ติดตั้งเป็นแอปบนหน้าจอโฮมได้ (PWA — ต้องเปิดผ่าน https), เปิดหน้าหลักได้แม้เน็ตหลุดชั่วคราว, สั่นเมื่อตอบ (Android), กันการซูมเองของ iOS ตอนแตะช่องกรอก

## เริ่มใช้งานบนเครื่อง

ต้องมี [Node.js](https://nodejs.org) 22.13 ขึ้นไป (ใช้ฐานข้อมูล SQLite ที่มีในตัว Node ไม่ต้องติดตั้งโปรแกรมเพิ่มหรือคอมไพล์)

```bash
npm install
npm start
```

เปิด http://localhost:3100 — ครั้งแรกระบบจะสร้างข้อมูลตัวอย่างให้อัตโนมัติ

| บทบาท | อีเมล | รหัสผ่าน |
|---|---|---|
| ครู | teacher@eduplay.local | teacher1234 |
| นักเรียน | student@eduplay.local | student1234 |
| ผู้ดูแล | admin@eduplay.local | admin1234 |

> บัญชีตัวอย่างสร้างเฉพาะตอน `NODE_ENV` ไม่ใช่ `production` เมื่อใช้งานจริงให้ตั้ง `ADMIN_EMAIL` และ `ADMIN_PASSWORD` แทน

ล้างข้อมูลแล้วเริ่มใหม่: `npm run seed` แล้ว `npm start` · ทดสอบ: `npm test`

**แข่งสดกับมือถือนักเรียนในห้องเดียวกัน:** ให้ครูเปิดเว็บผ่าน IP ของเครื่อง (เช่น `http://192.168.1.10:3100`) ไม่ใช่ `localhost` — หน้าโฮสต์จะเตือนและแนะนำ IP ให้เอง

### 📚 บทเรียน: 5 ระดับ หลายรูปแบบการเล่น เลือกจำนวนข้อและชุดคำถามได้

คลังเกมทั้งหมดเป็น "บทเรียน" 42 บท (ทุกหมวดมีอย่างน้อย 4 บท) อยู่ใน `server/lessons/` ใช้ร่วมกันทั้งเวอร์ชันเซิร์ฟเวอร์และเวอร์ชันเว็บ
- ก่อนเล่นเลือกได้: **ระดับ** ง่ายมาก/ง่าย/ปานกลาง/ยาก/ยากมาก · **รูปแบบ** ปรนัย/ถูกหรือผิด/ท้าเวลา/จับคู่พลิกการ์ด/เรียงตัวอักษร/เรียงลำดับ (ตามที่บทเรียนรองรับ) · **จำนวนข้อ** 6/10/15 · **ชุดคำถาม** ชุดที่ 1–4 (ตายตัว) หรือสุ่มชุดใหม่
- คณิต ฝึกสมอง และบางบทของปฐมวัยสร้างโจทย์อัตโนมัติตามระดับ (`gen`) ส่วนหมวดอื่นใช้คลังคำถามที่เขียนไว้ (`qa`, `pairs`, `tf`, `seq`) รวมกับคำถามจากเกมตกปลา (`fishing.js`) และเกมชุดเดิม (`legacy.js`)
- ตรวจคำตอบโดยไม่ต้องเก็บสถานะ: หน้าเกมส่ง `key` (ระดับ.รูปแบบ.จำนวน.ชุด.seed) กลับมา เซิร์ฟเวอร์สร้างชุดเดิมซ้ำแล้วตรวจ
- เพิ่มคำถาม: เปิดไฟล์หมวดใน `server/lessons/` แล้วเพิ่มแถว `[ระดับ, คำถาม, คำตอบ, ตัวลวง…, "§คำอธิบาย"]` · ตรวจด้วย `npm test`
- **ชั้นเรียนของแต่ละข้อ:** ชั้นคำนวณจากระดับของข้อเทียบกับช่วงชั้นของบทเรียน ส่วนข้อที่ตรวจแล้วว่าอยู่ชั้นอื่นกำหนดไว้ใน `server/lessons/grade-fix.js` · เมื่อผู้เล่นเลือกชั้นในโหมดเรื่องราว ทุกบทใช้เฉพาะคำถามของชั้นนั้น (ข้อไม่พอ → เสริมด้วยข้อชั้นเดียวกันจากบทอื่นในบ้าน หรือโจทย์ที่สร้างตามชั้น แล้วจึงทบทวนชั้นที่ต่ำกว่า) ไม่ดึงคำถามชั้นที่สูงกว่ามา
- ปฐมวัย: ระดับ 1–2 = อนุบาล · ระดับ 3–5 = ป.1 · ทุกข้อกำหนดตัวเลือกเอง · ข้อที่ต้องเติมตัวลวงอัตโนมัติจะไม่ใช้คำที่ซ้อนกับคำตอบ (เช่น รัง/รังนก) และไม่ใช้คำตอบของข้อที่ถามเรื่องเดียวกัน
- ฐานข้อมูลเดิมของเวอร์ชันเซิร์ฟเวอร์จะถูกย้ายโครงสร้างและเพิ่มบทเรียนให้อัตโนมัติเมื่อเปิดระบบ (เกมที่ครูสร้างไว้ยังอยู่ครบ)

### 🛡️ บัญชีผู้ดูแลระบบ (เวอร์ชันเว็บ)

1. Supabase → SQL Editor → รัน [`supabase/schema.sql`](supabase/schema.sql) อีกครั้ง (มีตาราง/ฟังก์ชันแอดมินเพิ่ม รันซ้ำได้)
2. สร้างบัญชีแอดมินแยก: Supabase → Authentication → Users → **Add user → Create new user** ใส่อีเมลและรหัสผ่าน แล้วติ๊ก **Auto Confirm User**
3. รัน [`supabase/make-admin.sql`](supabase/make-admin.sql) โดยเปลี่ยนอีเมลในไฟล์เป็นอีเมลบัญชีนั้น
4. เข้าสู่ระบบใหม่ จะเห็นเมนู **🛡️ แอดมิน** (`#admin`): ดูผู้เล่นทั้งหมด · ส่งของในร้านให้ผู้เล่น (เข้ากระเป๋าเมื่อผู้เล่นเปิดเว็บครั้งถัดไป) · ปลดล็อกของทั้งหมด/เติมเหรียญให้บัญชีตัวเองเพื่อทดสอบ

สิทธิ์ตรวจที่ฐานข้อมูลเสมอ (ฟังก์ชัน `is_admin`, `admin_list_players`, `admin_grant_item`) ผู้เล่นทั่วไปเรียกใช้ไม่ได้

### 🔐 บัญชีผู้ใช้ (Supabase)

ระบบบัญชีของเวอร์ชันเล่นบนเว็บใช้ [Supabase](https://supabase.com) (แผนฟรี) เก็บอีเมล รหัสผ่าน (เข้ารหัสแบบทางเดียว) และความคืบหน้า
ถ้ายังไม่ตั้งค่า เว็บยังเล่นได้ปกติ แค่ไม่มีปุ่ม “เข้าสู่ระบบ”

1. สมัคร/เข้าสู่ระบบที่ supabase.com → **New project** (ตั้งชื่อ, รหัสฐานข้อมูล, Region: Singapore)
2. **SQL Editor → New query** → วางทั้งไฟล์ [`supabase/schema.sql`](supabase/schema.sql) → **Run**
3. **Authentication → URL Configuration**
   - Site URL: `https://asdfzx009.github.io/game_wed/play/`
   - Redirect URLs: เพิ่ม `https://asdfzx009.github.io/game_wed/play/**`
4. **Project Settings → API** (หรือ **API Keys**) คัดลอก *Project URL* และ *anon / publishable key*
   แล้วใส่ใน [`docs/play/cloud-config.json`](docs/play/cloud-config.json):
   ```json
   { "supabaseUrl": "https://xxxx.supabase.co", "supabaseAnonKey": "eyJ... หรือ sb_publishable_..." }
   ```
   commit แล้วรอ GitHub Pages อัปเดต 1–2 นาที — ปุ่ม 🔐 เข้าสู่ระบบ จะขึ้นที่แถบเมนู

> anon/publishable key เป็นกุญแจสาธารณะ ใส่ในเว็บได้ ความปลอดภัยมาจาก Row Level Security ใน `schema.sql` (แต่ละคนอ่าน/เขียนได้เฉพาะข้อมูลตัวเอง)
> **ห้าม** ใส่ `service_role` / secret key ในไฟล์นี้เด็ดขาด

**เรื่องอีเมลยืนยัน:** Supabase แผนฟรีส่งอีเมลจากระบบในตัวได้น้อยมาก (ไม่กี่ฉบับต่อชั่วโมง) ถ้าจะให้ทั้งห้องสมัครพร้อมกัน เลือกอย่างใดอย่างหนึ่ง
- ปิดการยืนยันอีเมล: **Authentication → Sign In / Providers → Email → ปิด “Confirm email”** (สมัครแล้วเข้าเล่นได้ทันที แต่ “ลืมรหัสผ่าน” ยังต้องใช้อีเมล)
- หรือตั้ง SMTP ของตัวเอง: **Authentication → Emails → SMTP Settings** (เช่น Gmail App Password, Resend, Brevo)

สิ่งที่ผู้เล่นทำได้: สมัคร, ยืนยันอีเมล, เข้าสู่ระบบ, ลืม/ตั้งรหัสผ่านใหม่, เปลี่ยนรหัสผ่าน, ออกจากระบบ, ลบบัญชีถาวร
บัญชีใหม่เริ่มต้นใหม่ (150 🪙 ต้อนรับ) ความคืบหน้าตอนเล่นแบบไม่ล็อกอินแยกเก็บในเครื่อง ออกจากระบบแล้วกลับไปเล่นต่อได้

## การตั้งค่า (ตัวแปรแวดล้อม หรือไฟล์ `.env`)

ดูตัวอย่างใน [`.env.example`](.env.example)

| ตัวแปร | ความหมาย |
|---|---|
| `PORT` | พอร์ต (ค่าเริ่มต้น 3100) |
| `PUBLIC_BASE_URL` | URL จริงของเว็บ ใช้กับลิงก์แชร์และ QR แข่งสด (เว้นว่าง = ใช้ที่อยู่ที่ผู้ใช้เปิดเข้ามา) |
| `DATA_DIR` | โฟลเดอร์เก็บฐานข้อมูล SQLite |
| `APP_TIMEZONE` | เขตเวลาที่ใช้แสดงผลและจัดกลุ่มรายวัน (ค่าเริ่มต้น `Asia/Bangkok`) |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | สร้างบัญชีผู้ดูแลตอนเริ่มระบบ |
| `AI_PROVIDER` | `anthropic` หรือ `openai` (API ที่เข้ากันได้กับ OpenAI) |
| `AI_API_KEY` | คีย์ API — เก็บบนเซิร์ฟเวอร์เท่านั้น |
| `AI_MODEL`, `AI_API_URL` | ไม่บังคับ (URL ต้องเป็น https) |

ถ้าไม่ตั้งค่า AI ฟีเจอร์ “AI ช่วยสร้าง” จะปิดไว้และบอกครูให้ติดต่อผู้ดูแล (ระบบไม่สร้างเนื้อหาปลอม)

## นำขึ้นออนไลน์

แอปนี้มีเซิร์ฟเวอร์ (Node.js 22.13+ พร้อม Socket.IO และ SQLite ในตัว) จึง **ใช้ GitHub Pages ไม่ได้** ต้องใช้บริการที่รัน Node.js ได้และมีดิสก์ถาวร เช่น

- **Render:** เชื่อม repo นี้แล้วเลือก Blueprint ระบบจะอ่าน [`render.yaml`](render.yaml) ให้ (ต้องใช้แพ็กเกจที่มีดิสก์ถาวร) จากนั้นตั้ง `PUBLIC_BASE_URL`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`
- **Railway / Fly.io / VPS:** คำสั่ง `npm ci && npm start` และเมานต์ดิสก์ไว้ที่ `DATA_DIR`

## สิ่งที่แก้จากเวอร์ชันเดิม

| # | ปัญหาเดิม | การแก้ในเวอร์ชันนี้ |

| 2 | ลิงก์และ QR เป็น `localhost` | ใช้ `PUBLIC_BASE_URL` หรือที่อยู่ที่เปิดเข้ามา + เตือนและแนะนำ IP ในวง LAN |
| 3 | เหรียญ “คะแนนเต็ม” ไม่ปลดล็อก | ตรวจจากผลจริง (คะแนน = คะแนนเต็ม) ทั้งเกมและแบบทดสอบ รวมถึงหลังครูตรวจอัตนัย |
| 4 | Word Scramble ไม่สลับตัวอักษร | สลับจนกว่าจะต่างจากคำตอบ และแยกตัวอักษรไทยถูกต้อง (สระ/วรรณยุกต์ติดพยัญชนะ) |
| 5 | ข้อความทดสอบหลุดหน้าสาธารณะ | เนื้อหาตัวอย่างเขียนใหม่ทั้งหมด |
| 6 | AI ใช้โมเดลจำลอง / แสดงค่าตั้งเซิร์ฟเวอร์ให้ครู | เชื่อม Anthropic/OpenAI จริง ไม่มีโหมดปลอม ครูเห็นข้อความทั่วไป ผู้ดูแลเห็นวิธีตั้งค่า |
| 7 | คะแนนเฉลี่ยขัดกัน (50% กับ 75%) | ใช้สูตรเดียวกันทุกหน้า: “คะแนนเฉลี่ยทุกงาน” = ร้อยละเฉลี่ยของทุกการส่งงาน |
| 8 | วันที่ mm/dd/yyyy, “Choose File” | ตัวเลือกวัน/เดือน/พ.ศ./เวลาแบบไทย และปุ่มเลือกไฟล์ภาษาไทย รูปแบบวันที่เดียวกันทั้งระบบ |
| 9 | เวลาอาจไม่ใช่เวลาไทย | แสดงผล กราฟรายวัน CSV และการนับวันต่อเนื่องตาม `APP_TIMEZONE` ไม่ขึ้นกับเขตเวลาของเบราว์เซอร์ |
| 10 | เมนูมือถือ 3 บรรทัด ตารางเบียด | เมนูแบบพับ (☰) และตารางเลื่อนแนวนอนได้ |
